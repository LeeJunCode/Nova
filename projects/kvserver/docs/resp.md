# RESP 协议参考（v2）

> <https://redis.io/docs/latest/develop/reference/protocol-spec/>

## 1. RESP 是什么

RESP（REdis Serialization Protocol）是 Redis 客户端与服务器之间通信的协议：**客户端把命令编码成字节发过来，服务器把结果编码成字节回过去**，双方都按同一套格式收发。

## 2. 总体规则

1. **行终止符是 `\r\n`（CRLF）**，不是 `\n`。凡是以"行"为单位的部分都以 `\r\n` 结束。
2. **长度一律按"字节"计，不是字符**。数据里有中文/emoji 时，字节数 ≠ 字符数。
3. **消息是自定界的**：每种类型都自带"我有多长 / 到哪结束"的信息。接收方随时能判断"当前数据够不够一条完整消息、还差多少字节"。

## 3. 五种基本数据类型

RESP 靠**第一个字节**区分类型：

| 类型 | 首字节 | 格式 | 例子 |
|---|---|---|---|
| 简单字符串 | `+` | `+<文本>\r\n` | `+OK\r\n` |
| 错误 | `-` | `-<错误信息>\r\n` | `-ERR unknown command 'foo'\r\n` |
| 整数 | `:` | `:<十进制数>\r\n` | `:1000\r\n` |
| 批量字符串 | `$` | `$<长度>\r\n<数据>\r\n` | `$5\r\nhello\r\n` |
| 数组 | `*` | `*<个数>\r\n<元素1><元素2>...` | `*2\r\n$3\r\nGET\r\n$4\r\nname\r\n` |

## 4. 请求 vs 回复：不对称

**客户端发请求**：一条命令 = **一个数组，元素全部是批量字符串**。
```
PING           → *1\r\n$4\r\nPING\r\n
ECHO hello     → *2\r\n$4\r\nECHO\r\n$5\r\nhello\r\n
SET name lee   → *3\r\n$3\r\nSET\r\n$4\r\nname\r\n$3\r\nlee\r\n
GET name       → *2\r\n$3\r\nGET\r\n$4\r\nname\r\n
```

**服务器回回复**：可以用**任意类型**（简单字符串、错误、整数、批量字符串、数组）。

所以解析要分两个方向：
- **解析请求**（收客户端字节）：必须校验顶层是数组、元素是批量字符串。
- **编码回复**（发回客户端）：按每种回复类型拼字节。
