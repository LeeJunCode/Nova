# kvserver — 项目说明与范围定盘

## 这是什么

kvserver 是 Nova 的第一个学习子项目:**一个从零手写、可运行的简易 Redis**(Redis 风格的键值数据库服务器)。

- **参考对象**:Redis(<https://github.com/redis/redis>)——参考它的**分层架构与可观察行为**,不抄它的 C 内部实现。
- **学习载体**:通过一步步亲手实现它,学习 C++、计算机网络、数据结构、数据库。
- **基本功能**:一个网络服务器,接收客户端发来的命令,在内存里读写键值对,并支持重启后数据不丢。

## "完整"的定义:深度完整,而非宽度完整

真实 Redis 体量很大:数据模型十种上下、命令 200+ 个,外加 RDB/AOF/复制/哨兵/集群/Lua/模块/ACL 等。**全部复刻既不现实,对学习也无益。**

我们的做法:在**划定的子集**里做到三点——

1. 每个支持的命令,**行为与真 Redis 一致**(返回类型、错误消息、对不存在键 / 错误参数 / 类型不符的处理);
2. 协议与真 Redis **字节级兼容**;
3. 该有的机制**真实现**(存储、过期、AOF 持久化),不是空壳。

**验收标准**:把服务器跑起来,用真 `redis-cli` 连上去,凡声明支持的命令,表现必须与连真 Redis 一致(例如:GET 不存在的键必须回 `$-1\r\n`,而不是空串)。

## 范围对照:真实 Redis vs 我们要做

| 层 | 真实 Redis | 我们做 | 我们不做(原因) |
|---|---|---|---|
| 协议 | RESP2+RESP3、inline 文本命令、TCP+TLS、多 DB、AUTH | **RESP2**、TCP、单 DB | RESP3/TLS/inline 命令(以后可选),多 DB 不需要 |
| 数据模型 | String / Hash / List / Set / ZSet / Stream / Bitmap / HLL / Geo 等 | **第一版仅 String** | 其它类型留作扩展里程碑(练数据结构时再加) |
| 命令 | 200+ 个,含通用 key 命令 | 只实现 String 族 + 少量 key 命令(见"命令红线包") | 其它命令 |
| 内部存储 | sds、dict、quicklist、skiplist、intset、淘汰策略等 | 自研哈希表 + 动态字符串 | 不做 Redis 的内存优化花样,只要清楚可读的版本 |
| 持久化 | RDB + AOF + 混合 + 主从复制 | **仅 AOF**(追加日志 + 重启回放 + fsync 取舍) | RDB、复制 |
| 并发模型 | 单线程事件循环(epoll)+ 非阻塞 I/O | 先学多线程/线程池,**最终复刻 Redis 的单线程事件循环模型** | I/O 线程等优化 |
| 高可用 / 扩展 | 哨兵、集群、Lua、事务、pub/sub、ACL、模块 | 全部不做 | 明显超出"简易完整 Redis"边界 |

## RESP 协议要实现到什么地步

**收(请求方向)**——已实现,等待接线:
- 一条命令 = 一个顶层数组,元素全为 bulk 字符串;
- 粘包逐条处理、半包等待补齐、垃圾字节报协议错误;
- 容量防护:单条命令的元素个数、单个词的长度都要设上限。

**发(应答方向)**——需要补一个编码层,能发五种帧:
1. 简单字符串 `+OK\r\n`(SET 成功)
2. 错误 `-ERR ...\r\n`,错误消息带 Redis 风格大写错误码前缀,如
   `-ERR unknown command 'foo'`、`-ERR wrong number of arguments for 'get' command`
3. 整数 `:1\r\n`(INCR 结果、DEL 删除条数、TTL 剩余秒数)
4. bulk 字符串 `$3\r\nlee\r\n`(GET/ECHO),注意两个边界:
   - 值本身是空串 → 回 `$0\r\n\r\n`;
   - **GET 一个不存在的键 → 回 `$-1\r\n`(null bulk)**,不是空串——这是区分"躯壳"和"真完整"的细节。
5. 数组 `*n\r\n...`(以后 MGET/LRANGE 等),元素可为上述任意类型,含 null。

**两条与 redis-cli 兼容必须的行为**:
- 命令名**大小写不敏感**(真 Redis 查表前把命令名转小写;redis-cli 发的是小写);
- 每个命令做**参数个数校验(arity)**,个数不对回 `-ERR wrong number of arguments`。

## 命令范围(第一版"红线包")

- 连接:`PING` `ECHO`
- 字符串:`SET` `GET` `GETSET` `INCR` `DECR` `INCRBY` `APPEND` `STRLEN`
- 通用 key:`DEL` `EXISTS` `EXPIRE` `TTL` `TYPE`
- 数据类型:仅 String。Hash / List / Set 等作为扩展里程碑,由后续学习兴趣决定。

## 完成线(何时算"一个完整的简易 Redis")

1. 真 `redis-cli` 能连上,以上命令对拍全部一致;
2. SET / GET / DEL 存取与删除正确,GET 不存在的键回 null;
3. EXPIRE / TTL 过期机制真实生效;
4. 服务器重启后,之前 SET 的数据还在(AOF 回放);
5. 多个客户端同时连接互不卡死(单线程事件循环)。

## 开发路线(里程碑,每步独立可跑可测)

- ⓪ 测试框架 test-kit —— ✅ 完成
- ① TCP echo 服务器(阻塞单连接)—— ✅ 雏形完成
- ② RESP 协议解析 —— ✅ 解析完成;**剩余**:接线(网络层 + 分发 + 应答编码)
- ③ 内存存储:自研哈希表 + 动态字符串,落地 string 命令语义
- ④ 并发:多线程 → 线程池 → Redis 式单线程事件循环
- ⑤ 持久化:AOF
- ⑥ TTL / 过期收尾、错误消息打磨

## 明确不做(超出简易线)

RESP3、TLS、多 DB、inline 文本命令(以后可选)、RDB、主从复制、哨兵、集群、Lua 脚本、事务、pub/sub、ACL、模块;以及 String 之外的其它数据类型(扩展里程碑可选)。
